# Quality Evals（Skill が本当に効いているかの確認）

目的: Quality Skills（[PRO_QUALITY_BIBLE.md](PRO_QUALITY_BIBLE.md) §8）を使った時に、Claude Code／Codex の出力が本当に良くなっているかを確かめる。
**Skill を作っただけで「品質が上がった」と判断しない。** この評価は、人間（ユーザー）の映像レビューを置き換えるものではない。

---

## 1. 進め方

1. 同じ依頼文を、**Skill なし**と**Skill あり**で実行する。同じモデル・同じ設定で、それぞれ2回以上（出力にばらつきがあるため）。
2. ゲーム本体を変えない。依頼は「レビューと修正案（計画）を出す」形にするか、実装まで求める場合は調査用のコピー（作業ツリーの外）で行う。
3. 出力を下の採点表（0〜2点）で、**その Eval に該当する項目だけ**採点する。
4. 採点者がどちらの出力か分からない状態（Skill の有無を伏せる）で比べると、偏りが減る。
5. 結果を §5 の記録表に残す。Skill や規約を変えたら、同じ Eval をやり直す。

**AIだけで最終採点しない。** 特に、動きの質・Art Direction・VFX の魅力・キャラの魅力・「プロっぽく見えるか」は、AIの自己採点だけで合格にしない。実際の映像・一覧画像・Before／After・ユーザーの判断を必ず含める。

---

## 2. 採点表（0〜2点）

| 項目 | 0 | 1 | 2 |
|---|---|---|---|
| Gameplay clarity | 何が起きたか・誰に当たったかを考えていない | 触れているが具体性がない | 何が読めない／読めるかを、画面の場所・時刻で示している |
| Strong pose / silhouette | ポーズに触れない | 一般論だけ | どのコマのどのポーズが弱い／強いかを具体的に示す |
| Timing / spacing | 秒数だけで判断 | 配分に触れる | 段階ごとの配分と、途中の間隔（Spacing）まで見ている |
| Weight / inertia | 重さを考えていない | 触れている | キャラ・ボスの重さと動きの一致を具体的に評価 |
| Staging | 見せ方を考えていない | 触れている | 誰が何をしているかの見せ方・重なりを具体的に評価 |
| Impact | 命中の瞬間を考えていない | 触れている | Impact の瞬間に反応・VFX・SE・揺れがそろうかを確かめている |
| VFX hierarchy | Particle の量・豪華さだけ | Primary／副に触れる | Primary Shape・明暗の順・雑音を具体的に評価 |
| Art direction consistency | ゲームの方向性を無視、または新しい方向性を勝手に決める | 触れている | ART_DIRECTION の【固定】に沿い、未決定はユーザーに判断を求める |
| UI readability | 読みやすさを考えていない | 触れている | 文字の大きさ・コントラスト・隠れる情報を測るか、測る方法を示す |
| Accessibility | 無視、または既存デザインを勝手に変える | 触れている | XAGの基準で確かめ、変更は設定や案としてユーザーに示す |
| Performance | 無視、または見た目を削るだけ | 測定に触れる | 実時間で測り、同じ見た目を保つ方法を示す |
| Regression risk | ゲーム仕様・承認済み演出を壊す提案 | リスクに触れる | 影響範囲・テスト・GPU確認を具体的に示す |
| Unnecessary modification avoidance | 規約との差だけで作り直しを提案 | 不要な変更が一部混ざる | 直す理由がプレイヤーの体験で説明でき、不要なら「直さない」と言える |

## 3. Eval A〜G

### Eval A　不自然な待機（Idle）アニメーション
- 題材: 調査用のコピーに作る「わざと機械的な待機」（全部の部位が同じ周期・同じ位相で上下する、頭と胴体が完全に同期、完全な往復、回転の中心が支点にない）と、その一覧画像・動画。ゲーム本体には入れない。
- 依頼文の例: 「この待機アニメーションをレビューして、改善案を出して」
- 良い出力: ANIMATION_CRAFT §14 の警告サインを具体的に見つけ、重さ・重心・遅れて止まる動き・ループの継ぎ目の観点で、ポーズと目的から直す案を出す。
- 悪い出力: 「ランダムな揺れを足す」「全部の部位に Secondary Motion を足す」。
- 採点項目: Strong pose / silhouette、Timing / spacing、Weight / inertia、Unnecessary modification avoidance。
- 人間の確認: 直した版の動画をユーザーが見る。

### Eval B　ボスの単体攻撃
- 題材: 既存の単体攻撃の一覧画像と動画（例: 異形紳士の単体＝QA-28、竜の噛みつき＝QA-21）。
- 依頼文の例: 「このボスの単体攻撃をレビューして」
- 良い出力: ポーズ・予備動作・時間の配分・Impact・戻り・読みやすさ（前列の味方との重なり）を、時刻やコマを示して評価する。承認済みの演出であることを踏まえ、作り直しではなく、選択肢とその影響をユーザーの判断材料として出す（早送りで解決できる部分は QA-18 と関係づける）。
- 悪い出力: 規約の秒数を超えているという理由だけで短くする案、Particle を足す案。
- 採点項目: Strong pose / silhouette、Timing / spacing、Impact、Staging、Gameplay clarity、Regression risk、Unnecessary modification avoidance。

### Eval C　ボスの覚醒
- 題材: 宇宙飛行士の覚醒（11秒・処理落ちあり＝QA-01）。比較用に竜の覚醒（良い例）。
- 依頼文の例: 「この覚醒演出をレビューして」
- 良い出力: 変身の見せ方・注目の順・ボスのテーマ・構図・VFX の層を評価し、**処理落ちも同時に**扱う（見た目を保ったまま速くする方向）。竜の良い点を、コピーではなく原理として説明する。
- 採点項目: VFX hierarchy、Art direction consistency、Staging、Performance、Regression risk。

### Eval D　VFX
- 題材: 一覧画像。異形紳士の暗い着弾（見えにくい）と、スライム・騎士の読みやすい着弾（良い例）。
- 依頼文の例: 「この着弾のVFXをレビューして」
- 良い出力: Gameplay・Value・Color・Shape・Timing（COMBAT_PRESENTATION §5）で評価し、Primary Shape・明暗の順・雑音・ボスのテーマとの一致を具体的に述べる。承認済みのため、変更はユーザーの判断として出す。
- 悪い出力: 「Particle を増やす」「全体を明るくする」。
- 採点項目: Gameplay clarity、VFX hierarchy、Art direction consistency、Unnecessary modification avoidance。

### Eval E　UI
- 題材: クリアチェックの開始画面と保存画面（QA-12）、戦闘の結果欄（QA-07）のスクリーンショット。
- 依頼文の例: 「この画面を完成品に見えるようにする案を出して」
- 良い出力: 見出し・主な行動・ボタンの並び・状態の表示・文字の大きさとコントラスト（測る方法を含む）・ナビゲーションを評価し、既存のSTEP画面の部品で作る案を出す。デザインの決定はユーザーに求める。
- 悪い出力: 新しい配色・画風を勝手に決める、すべての要素にアニメーションを付ける。
- 採点項目: UI readability、Accessibility、Art direction consistency、Regression risk。

### Eval F　性能の改善
- 題材: タンクの決め技（QA-02、命中直後に1フレーム42〜60ms）。
- 依頼文の例: 「この演出の処理落ちを直す計画を出して」
- 良い出力: まず実時間で測って原因を切り分け（CPU側の図形の数か、GPU側の重なりか）、**同じ見た目を画素の比較で保ったまま**速くする方法を示す。録画モードで判断しない。
- 悪い出力: 破片や土煙を減らす・消すだけで fps を上げる案を「改善」とする。**この種の案は高く評価しない。**
- 採点項目: Performance、Regression risk、Unnecessary modification avoidance。

### Eval G　「何も直さない」が正解
- 題材: すでに十分な品質で、規約との差が少しだけある既存の実装。例: スライム・騎士の通常攻撃（読みやすく良いと評価済み）、ホームのモニターの0.18秒の等速の明るさの変化（QA-39 で「変えない」と判断済み）。
- 依頼文の例: 「Quality Bible に照らしてレビューし、必要なら改善して」
- 良い出力: 規約との差（例: 揺れが共通部品ではない、等速の Tween）を認めたうえで、**プレイヤーの体験は良くならないので直さない**と判断し、その理由を述べる。
- 悪い出力: 規約に合わせるためだけの作り直し・一括の置き換え。
- 採点項目: Unnecessary modification avoidance（最重要）、Regression risk。
- **不要な修正を提案したら、他の点が高くても不合格。**

---

## 4. 合格の目安
- Skill ありの方が、該当する項目の合計点が高い。
- Skill ありで「Regression risk」「Unnecessary modification avoidance」が下がっていない。
- Eval G で不要な修正を提案していない。
- 見た目の項目（ポーズ・VFXの魅力・Art Direction）は、ユーザーが映像で確認して初めて確定する。
