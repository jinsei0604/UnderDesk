# Accessibility（遊びやすさ・安全）

[PRO_QUALITY_BIBLE.md](PRO_QUALITY_BIBLE.md) の判断基準が優先する。主な参考資料は Xbox Accessibility Guidelines（XAG）。出典のIDは [EXTERNAL_REFERENCES.md](EXTERNAL_REFERENCES.md)（`[X101]` など）。

- この文書は Release Gate の「読めないUIなし」「重大なAccessibility問題なし」（PRO_QUALITY_BIBLE §1.1）を判定するための基準。
- **Accessibility を理由に、既存のデザイン・承認済みの演出を勝手に変えない。** 問題が見つかったら測定結果と案をユーザーに示す。設定で弱める・切る形を優先して検討する。
- XAGの数値は「この値を満たせば絶対に安全・十分」という意味ではない。特に光過敏（§5）は、危険になりうる演出そのものを避ける。

---

## 1. Text（文字の大きさ）`[X101]`
- XAGの最小の目安: PCでは1080pの画面で18px以上（4Kで36px）。
- **大きさの測り方**: フォント設定の数字ではなく「本文の高さ」＝ 最も高いアセンダーの上端から、最も低いディセンダーの下端までの画素数。実際の画面のスクリーンショットで測る。縁取りの画素は、背景とのコントラストが2:1を超えるものだけ含める。
- このゲームは1280×720の論理解像度を拡大して表示する（`canvas_items`）。**論理14px（UI_UX §2）を機械的に18pxへ変えない。** 1920×1080では1.5倍に拡大されるので、実際の画面で本文の高さを測って評価する。
- 1280×720のウィンドウで遊ぶ場合の目安は、XAGの1080pの値を 720/1080 倍した値（18px → 12px）。これはこのプロジェクトの換算で、XAGに書かれた値ではない。
- 今の文字サイズ（`rbm_ui_theme.gd`、論理px）: タイトル40・見出し20・本文16・小さい文字13。1080pでの本文の高さは**未測定**（[QUALITY_AUDIT_STANDARD_DELTA.md](QUALITY_AUDIT_STANDARD_DELTA.md)）。
- 日本語（漢字・かな）の大きさの測り方はXAGに明記がない（**UNVERIFIED**）。このプロジェクトでは当面、字面の上端から下端までを測る。
- 文字の拡大（将来の検討）: XAGは最小サイズの200%まで、内容を失わずに拡大できることを求める。将来に備えて、文字サイズはテーマの定数（`FONT_SIZE_*`）に集め、欄の大きさを文字に合わせて伸ばせる作りにしておく。固定の小さな欄に文字を詰め込まない。
- フォントは対応する言語の文字をすべて含むこと `[X101]`（日本語フォントを同梱していない問題は QA-16）。
- 2行を超える文章: 日中韓の文字は1行40字まで、行間は1.5倍が目安 `[X101]`。

## 2. Contrast（コントラスト）`[X102]`
| 対象 | 最低のコントラスト比 |
|---|---|
| 標準の大きさの文字・ゲームに必要な情報を持つ要素 | 4.5:1 |
| 大きい文字（PCで1080p時36px以上）・大きな要素 | 3:1 |
| 無効状態（押せない）の文字 | 3:1 |
| 入力欄の文字・プレースホルダー | 4.5:1（大きい文字は3:1） |
| 高コントラストモード（将来、作る場合） | 7:1 |

- **背景が変化する場所では、最もコントラストが低くなる部分で測る**（松明・炎・空・VFXの上の文字）。
- ロゴ、純粋な装飾は対象外。
- 改善の手段: 下地（不透明・半透明の帯）、縁取り、文字色の変更。
- 測り方: スクリーンショットから文字の色と、文字の後ろで最も条件の悪い背景の色を取り、コントラスト比を計算する（WCAGと同じ相対輝度の式。ツールの例: Colour Contrast Analyser）。
- 画像の中に文字を焼き込まない（ロゴを除く）。焼き込むと下地や色を後から直せない `[X102]`。

## 3. Color（色だけに頼らない）`[X103]`
- 色だけで情報を伝えない。ゲームに必要な情報は、形・アイコン・文字・動き・位置のどれかを併用する。
- 押せない状態を灰色だけで示さない。文字やアイコンを併用する。
- 赤と緑のように、色覚の違いで区別しにくい組み合わせだけで区別しない。
- 今分かっていること: キャラ名は「炎属性・勇者」のように属性を文字でも示している。HP・SPのバーは数字も出している。支援のVFX（強化=赤・回復=緑）が色以外でも区別できるかは**未確認**（DELTA）。

## 4. Motion（揺れ・動き）`[X117]`
- 画面揺れ・揺れ動くカメラ・モーションブラーは、避けるか、切る（弱める）設定を用意する。
- ゲームに必要なもの以外の、繰り返しの上下・左右の動きを避ける。
- 文字のある画面で、点滅・自動で動き続ける内容があるなら、止める・隠す手段を用意する（ゲームプレイ中の周辺の動きは対象外）。
- このプロジェクトでの適用: 今すぐ設定画面を作る必要はない（設定画面は QA-14）。揺れを共通部品にする時（QA-20）に、**強さの倍率（0〜100%）を受け取れる作り**にしておく。演出ごとの揺れを今のまま増やさない。

## 5. Photosensitivity（光過敏）`[X118]`
**危険になりうる演出そのものを避ける。** 警告画面を出すことより、内容をなくすことを優先する（XAG 118）。

| 種類 | 何を閃光・模様とみなすか | 失敗とみなす条件 |
|---|---|---|
| 輝度の閃光 | 輝度が10%以上変化する（白い画面の最大輝度を100%とする）。暗い側の輝度が0.8未満 | 約3回/秒を超える／画面の約20%以上を占める／弱い閃光でも長く続く |
| 赤の閃光 | どちらかの端が彩度の高い赤（R/(R+G+B) ≥ 0.8）で、(R−G−B)×320 の変化が20を超える。通常の閃光より小さな変化で該当する | 同上 |
| 縞模様 | コントラストの高い帯が交互に並ぶ | コントラスト差が10%を超え、画面の約20%以上を占める |

- 対処の方向（XAG 118）: 明暗の差を減らす、回数を減らす、面積を小さくする、赤の彩度を下げる。
- **上の条件を下回れば絶対に安全、という意味ではない。**
- 以前の規約「全画面の閃光は0.12秒以内・1秒3回まで」（COMBAT_PRESENTATION §4.4）は設計の目安として残すが、安全の判定には使わない。
- 測り方（このプロジェクトの手順）:
  1. 演出を `--fixed-fps 60` で全コマ書き出す（調査用のコピーで行う。ゲーム本体は変えない）。
  2. 各コマの相対輝度と、前のコマから変化した画素の面積の割合、赤の条件に当たる画素の割合を計算する。
  3. 1秒の窓で、条件を満たす閃光の回数を数える。縞模様は、強い縞が画面の約20%以上を占めるコマがないかを見る。
  4. 最終確認は専用の検査ツール（例: Harding FPA）が望ましい。導入するかはユーザーの判断。
- 確認する候補（**未測定**、DELTA）: タンクの決め技のインパクトフレーム（白黒2コマ）、武者の全体攻撃の白い画面、宇宙飛行士の爆発の白い閃光、炎・赤の全画面効果、竜の覚醒の暗転、縞模様に見える効果（雨・格子・走査線など）。

## 6. 操作（入力）
- マウス・キーボードで全機能に届くこと。フォーカスが見えること（UI_UX §13・§14）。
- ゲームパッド対応はユーザーの判断（QA-29）。対応する場合の基準は UI_UX §14。

## 7. Release Gate での扱い
| 区分 | 例 | 扱い |
|---|---|---|
| 重大（Release Gate違反） | XAG 118 の失敗条件に当たる演出／ゲームに必要な文字が読めない（§1・§2を大きく下回る）／ゲームに必要な情報が色だけ | 完成扱いにしない。P0またはP1 |
| 改善（Polish） | 設定がない（揺れ・文字の拡大・高コントラスト）、補足の文字がわずかに目安を下回る | P2として、ユーザーと優先度を決める |
