# 確認チェックリスト

作業の最後に、該当するリストだけを確認して報告に含める。詳しい理由は各章を参照。
「確認した」「確認していない（理由）」を分けて書く。
（このリストの A〜G は作業の種類の区分。PRO_QUALITY_BIBLE §3 の Review A〜L とは別のもの）

---

## A. どの作業でも
- [ ] 作業前に `git status` を見て、他の未コミット変更と自分の変更を分けた（reset／checkout／stash／clean は使っていない）
- [ ] 直す理由は「プレイヤーが感じる完成度が上がる」こと（規約違反だけ・数値に合わせるためだけが理由ではない）
- [ ] ゲーム仕様（ダメージ・行動・覚醒条件・Clear Check・オンライン・保存）を変えていない
- [ ] Release Gate を満たしている（[PRO_QUALITY_BIBLE.md](PRO_QUALITY_BIBLE.md) §1.1）
- [ ] 関連GUTが通る。全GUTは [PRO_QUALITY_BIBLE.md](PRO_QUALITY_BIBLE.md) §5（Test）の条件に当たる時に実行し、実行した／しなかった理由を書いた（テストを削っていない）
- [ ] 実GPUで実際の画面を確認した
- [ ] 変更は1つの問題に絞っている
- [ ] 見た目の良し悪しを、規約や Skill を読んだことではなく、実際の映像とユーザーの判断で決めた
- 見た目を作る・変える作業では:
  - [ ] 他の画面・キャラと同じゲームに見える（[ART_DIRECTION.md](ART_DIRECTION.md)）
  - [ ] 背景が主役（キャラ・命中点・大事な文字）を食っていない
  - [ ] どこを見ればよいか（Focus）が明確（ART_DIRECTION §8）

## B. 戦闘演出（ボスの技・味方の技・覚醒）
動き（[ANIMATION_CRAFT.md](ANIMATION_CRAFT.md)）
- [ ] Key Pose が強く、1コマ止めても何をしているか分かる
- [ ] シルエットで動きが読める（武器・腕が体に埋もれない）
- [ ] Spacing が機械的でない（等間隔・すべて同じ ease になっていない）
- [ ] 弧（Arcs）が不自然でない（関節の動きが直線になっていない）
- [ ] 遅れて止まる動き（Follow Through／Overlap）が、あるべき所にある（全部の部位ではない）
- [ ] 機械的な Tween の警告サインがない（ANIMATION_CRAFT §14）

構成とタイミング（[COMBAT_PRESENTATION.md](COMBAT_PRESENTATION.md)）
- [ ] Impact の瞬間が1つに決まっていて、被弾反応・VFXのピーク・SEがそろう（§1）
- [ ] 長さが階層の目安に収まる。収まらないなら理由がある（§2）
- [ ] 予備動作・余韻が長すぎず、何も起きない時間がない（§3）
- [ ] 被弾した味方・対象が、攻撃者やVFXに長く隠れない（§3.8・§5.2）
- [ ] 揺れ・Hit Stop・Flash の強さが技の重さに合っている（全攻撃に入れていない）（§4）

VFX（COMBAT_PRESENTATION §5）
- [ ] この技の Primary Shape が何か言える（§5.4）
- [ ] 明暗の優先順（Value hierarchy）があり、一番明るい所が一番見てほしい所（§5.5）
- [ ] 何が起きたか・誰に当たったか（Gameplay clarity）を壊していない
- [ ] 目的のない雑音（Visual clutter）を増やしていない（§5.7）
- [ ] ボス・技のテーマと形・色が一致している（§5.6、ART_DIRECTION §3.1）
- [ ] 暗い背景でも着弾が見える（コントラスト）（§5.2）
- [ ] 新しいVFXがドット絵として一貫して見える（1px／2px格子が基本。外れる場合はユーザーが動画で承認済み）（§6.1）

安全・その他
- [ ] 全画面の閃光・赤の閃光・縞模様が、XAG 118 の失敗条件（約3回/秒を超える・画面の約20%以上・長く続く）に当たらない（[ACCESSIBILITY.md](ACCESSIBILITY.md) §5）
- [ ] 揺れを新しく作るなら、強さの倍率を受け取れる共通部品にした（ACCESSIBILITY §4）
- [ ] 覚醒後の攻撃が通常版と一目で違う（§7）
- [ ] 中断・REWIND・画面が隠れた時に、見た目と音が元に戻る（§9）
- [ ] 戦闘状態が演出の前後で変わらない（`simulation_unchanged`）
- [ ] `tools/verify_<対象>_gpu.gd` で3画面・5属性・カウンター・中断を確認した
- [ ] 一覧画像か映像で、動き・タイミング・impact・読みやすさを見た

## C. 性能
- [ ] 実時間で測り、平均58fps以上・33ms超0・20ms超2%以下（[PERFORMANCE.md](PERFORMANCE.md) §1）
- [ ] 同じ演出を同じ起動の中で測り、初回だけの停止がない（再生中に初めて読み込む素材がない。停止を戦闘開始など別の瞬間へ移していない）（[PERFORMANCE.md](PERFORMANCE.md) §2.1）
- [ ] 戦闘を始める前の画面からすぐに戦闘を始める最速の経路でも、演出の開始時に未読の素材がない（間に合わない時は演出の開始の境界で待ち、待つ間に HP の表示・次の行動が先へ進まない）（§2.1）
- [ ] 事前読み込みを増やした時は、テクスチャメモリの増分・保持期間・解放条件・必要性を報告し、現在の基準値から明らかに増えるならユーザーの承認を得た（§2.1）
- [ ] 1920×1080でも測った
- [ ] 再生のたびに大きな素材を読み込んでいない、`_process` で毎フレーム物を作っていない（§2）
- [ ] 見た目を削っただけで速くしていない（同じ見た目を画素の比較で確かめた、またはユーザーが変更を認めた）（§1.2）

## D. UI・画面
- [ ] 読ませる文字は14px以上（論理px）。1920×1080の実画面で本文の高さを測った、または測っていないと報告した（[ACCESSIBILITY.md](ACCESSIBILITY.md) §1）
- [ ] 文字のコントラストが4.5:1以上（大きい文字・無効状態は3:1以上）。背景が変わる所は最悪の場所で測った（ACCESSIBILITY §2）
- [ ] 絵の上の文字に下地か縁取りがある（[UI_UX.md](UI_UX.md) §2）
- [ ] 状態・属性・結果を色だけで伝えていない（ACCESSIBILITY §3）
- [ ] 大事な情報がスクロールの奥や他の欄の裏に隠れない
- [ ] 主な行動（Primary）が1つに決まって一番目立ち、主ボタンと「戻る」の並びが他の画面とそろう（UI_UX §12）
- [ ] ボタンの hover／pressed／focus／disabled が分かり、フォーカスが見え、二重押しで2回動かない（§3）
- [ ] Loading・0件・エラー・削除などの確認の状態に、整った表示がある（§13）
- [ ] 画面の出入りが唐突でない。動きは目的のある所だけ（§4・§15）
- [ ] 英語表示でも未翻訳・はみ出しがない（§9）
- [ ] エラーに内部コードだけを見せていない（§8）
- [ ] 1280×720以外のウィンドウ・比率でも崩れない

## E. タイトル画面・ボスの部屋（Codex担当）
- [ ] 見た目・演出の変更はCodexの担当範囲で、承認を受けている
- [ ] ループのつなぎ目で絵が飛ばない（[UI_UX.md](UI_UX.md) §7）
- [ ] 部屋の作成で0.2秒以上止まらない
- [ ] ロゴ・START・入力・フェードは共通シェルのまま
- [ ] 不自然な変形・回転中心・機械的なTween感がない（[ANIMATION_CRAFT.md](ANIMATION_CRAFT.md) §13・§14）
- [ ] 文字（ロゴ・START）の後ろで動き続ける・点滅するものが、読みにくさや負担になっていない（ACCESSIBILITY §4）

## F. 音
- [ ] SEが Impact の瞬間に鳴る（固定タイマーで別に鳴らしていない）（[AUDIO.md](AUDIO.md) §2）
- [ ] 攻撃の大きさで pitch・低音・立ち上がり・余韻に差がある（§3）
- [ ] その瞬間に一番聞かせたい音が聞こえる（Mix hierarchy、§6）
- [ ] 大事な音が他の音に埋もれていない（Masking、§7）
- [ ] 一番音が重なる場面でマスターが0dBを超えない（Clipping、§8）
- [ ] 中断・REWINDで音が止まる
- [ ] ゲーム内の音量を録画用に変えていない

## G. 翻訳・文字
- [ ] 新しい表示文字は `tr()` を通り、`localization/ui_strings.csv` に英語がある
- [ ] CSVを変えたら `.translation` を取り込み直した
- [ ] 日本語の画面に英語が混ざっていない（固有名詞は統一）
